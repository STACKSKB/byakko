# Linux playback monitor implementation

2026-09-22. `audio_sample_linux.rs` adds original Rust FFI bindings to the user's installed `libpulse.so.0`. No PulseAudio source/header implementation or shared library is copied into the repository or distributed binary. The system library is LGPL; it is loaded at runtime rather than bundled. Product Cargo dependencies are unchanged.

The sampler connects without autospawning a daemon. It queries the default playback sink, then obtains that sink's exact monitor source name and index. It connects to the explicit monitor with DONT_MOVE and verifies the actual stream source index at startup and before reading each sample batch. It does not use the ambiguous default-source or default-monitor shortcuts. Missing sinks/monitors, routing mismatches, failed connections and timeouts are errors, never a fallback to microphone capture.

Capture requests48kHz float32 little-endian mono from a PulseAudio server or PipeWire's Pulse-compatible server. The nonblocking main loop is pumped a bounded number of times; packet count and decoded byte count are capped. Each startup/introspection stage has a3second deadline. Introspection operations are cancelled/unreferenced before their callback reply storage goes out of scope. RAII releases the stream, context, main loop and loaded library. No recordings are saved.

Primary API references: [introspection structures and callbacks](https://0pointer.de/lennart/projects/pulseaudio/doxygen/introspect_8h_source.html), [states and flags](https://0pointer.de/lennart/projects/pulseaudio/doxygen/def_8h.html), [stream source index](https://0pointer.de/lennart/projects/pulseaudio/doxygen/stream_8h.html), [operation lifecycle and license notice](https://0pointer.de/lennart/projects/pulseaudio/doxygen/operation_8h_source.html). These were used as interface specifications, not implementation sources.

Linux target compilation, Clippy and cross-linking pass. Live sampling, server teardown, default-output changes and audio-driven keyboard output on Linux remain unverified. `wsl --list --verbose` finds only the stopped Docker-managed distribution on this Windows host; no Linux desktop/audio server is available for a representative test. The existing `sample_audio` example can probe sample rate/count/peak without saving audio. The Windows tone/camera integration check does not establish Linux behavior.
