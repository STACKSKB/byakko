# Engineering status and evidence carried forward

This note separates dated observations from the active rules in [AGENTS.md](../AGENTS.md). The [parity ledger](parity-status.md) and feature-specific `iced-*-acceptance.md` notes carry the detailed acceptance record. A successful read, headless test, or transport-accepted setter establishes only its stated scope.

## Current implementation (2026-09-26)

The product boundary is `byakko-core`, `byakko-devices`, and the Iced `byakko-desktop`, with an independent `byakko-cli`. The egui application and root GUI command were retired in commit `3471866`; the root package retains research tools. The pure model, memory backend, Nia87 adapter, and Iced keymap, macro, built-in global lighting, per-key picture, scalar settings, and native archive capture/export workflows exercise the boundary. Archive review/restore APIs remain developer research tools outside the public pre-alpha UI. See [backend architecture](backend-architecture.md), [frontend contract](frontend-contract.md), and [archive scope](configuration-archives.md).

The workspace keeps the keyboard visible across key, macro, lighting, per-key color, and settings controls. Scalar settings appear together. Page navigation issues no reads. Connection refresh loads scalar sections once. Macro discovery is passive, with a separate correlated ticket and foreground priority between slot reads on the serialized executor; recording cancels the scan after the active slot. The library shows configured or bound slots, Add chooses the first unbound free slot, and selecting a macro reads its editable snapshot. Unknown slots are never assumed empty. Explicit reads remain available for failed or invalidated feature snapshots. Lighting choices use coalesced intent queues; normal use needs no Read/Apply. The native color picker and modal discard prompt are in place. The Windows release containing the workspace changes was opened for user validation; final rendered layout and physical LED response remain for that review. See [desktop UI architecture](desktop-ui-architecture.md), [macro acceptance](iced-macro-acceptance.md), and [lighting acceptance](iced-lighting-acceptance.md).

The physical-coordinate key selector is shared by keymap and per-key color views. On 2026-09-23 the user confirmed the rebuilt Keys page showed a TKL board and key selection worked after a physical USB replug. General one- and two-modifier shortcuts use an optional portable descriptor and staged Iced editor; memory-backend selection/apply/readback tests and Nia87 encoding tests passed, while physical shortcut output remains unverified. See [keymap acceptance](iced-keymap-acceptance.md).

Iced's read-only bounded USB discovery worker and idle reconnect flow have a user-assisted unplug/replug and fresh-read observation from 2026-09-23. Each desktop executor keeps an immutable selected HID target, including recovery opens; a failed target check cannot fall back to another unique match. Feature-specific conflict or failed-write diagnostics survive disconnect and require deliberate manual reads before automatic reconnect. Linux GUI/runtime acceptance remains open. See [discovery acceptance](iced-discovery-acceptance.md) and [Linux handoff](linux-handoff.md).

Iced screen-average lighting uses a pure lifecycle, bounded selected-device frame path, and separate OS sampler. Playback music shares that lifecycle with 32-band OS audio sampling and portable temporary controls translated by the Nia87 adapter. Start requires a verified editable lighting baseline; Stop/close require verified restoration. These Iced paths have headless evidence only. Physical streaming, focus loss, disconnect, stored-host-mode exit, and Linux runtime acceptance remain open. A recognized mode left by a crash can be replaced only by an explicit onboard-effect choice; unknown responses stay opaque and startup sends no automatic reset. See [host lighting migration](iced-host-lighting-migration.md) and [lighting acceptance](iced-lighting-acceptance.md).

## Physical evidence and open gates

- Rebuilt Iced picture submissions repeatedly uploaded full images and visibly changed colors. A later explicit read matched all 128 entries. The 2026-09-25 camera capture shows retained-brush painting of F2 and F3 green, without establishing subsecond batching. Earlier picture recovery failed and remains unresolved; these observations do not prove power-cycle persistence, general recovery, or archive restore. See [picture acceptance](iced-picture-acceptance.md) and [fault verification](../Research/configuration-fault-verification.md).
- Physical Iced steady-effect selections visibly changed the board; ordinary lighting setters report transport acceptance after pacing. Global picture-effect selection and RGB picture storage are separate. See [lighting acceptance](iced-lighting-acceptance.md).
- Settings stage one scalar field per native transaction. An official-app settings capture and the Iced session give reference and implementation evidence, not physical Iced write/restore acceptance. See [settings acceptance](iced-settings-acceptance.md).
- A fault-injected whole-archive apply produced unexplained Windows collateral changes and failed automatic recovery. A later explicit restore verified; the collateral/recovery gate remains open. The dated Linux raw-white restoration also reported nonidentical bytes. The [2026-09-27 Windows boundary comparison](../Research/rgb-white-boundary-20260927.md) establishes the intentional official Nia87 global-lighting convention: semantic `FFFFFF` sends `FAFFFA`, which reads as semantic `FFFFFF`; literal native `FFFFFF` read back as `B4B4B4`, with no general channel cap. Exact native archive verification must still report nonidentical bytes, but this white convention is not a bug or release gate. The public archive UI remains capture/export-only. See [fault verification](../Research/configuration-fault-verification.md), [archive acceptance](iced-archive-acceptance.md), and [Linux handoff](linux-handoff.md).
- Linux has read-only identity, keymap, lighting, settings, colors, macro, and archive evidence, plus bounded CLI write/restore and user-observed Iced behavior on an attached Nia87. Those observations do not accept every GUI feature or physical write path. Windows and Linux use different units; keep their baselines and observations separate. See [Linux handoff](linux-handoff.md).
- A macro Save & assign readback failure was reproduced on Windows at page 1. The investigation verified 2 s settling and a 26-byte final page (250 writable bytes), avoiding transitional readback and picture collateral. One readback remains; duplicate mismatch/identity checks are absent. Bounded keyboard playback and native save/assign/restore passed. Linux write-path acceptance remains open. See the [pacing investigation](../Research/macro-write-pacing-20260926.md) and [session/transaction audit](desktop-ui-architecture.md).
- General macro mouse/toggle/hold playback timing, shortcut output, host lighting, and Iced settings gestures remain open; the simple Windows keyboard macro and shared settings executor have physical evidence. Headless tests do not establish the remaining behaviors. See the [parity ledger](parity-status.md).

Preserve protocol fixtures, dated research, and captures. Do not rewrite historical observations to match later policy changes; the active one-pass read policy is in [AGENTS.md](../AGENTS.md).
