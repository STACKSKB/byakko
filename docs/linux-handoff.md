# Linux validation status

The native Linux client uses the same core and protocol rules as Windows. Install the device-specific permission rule and helper using [Linux installation](linux-install.md), then build using [source build](source-build.md).

Read-only configuration access has bounded hardware evidence. This does not establish every distribution, GUI feature, write path or recovery outcome. Configuration permissions do not grant the separate onboard notification collection; listener permission and runtime acceptance remain open.

Local device baselines, account ACLs, machine paths and coordination records are private. Public protocol behavior and remaining product gaps are described in [engineering status](engineering-status.md) and [parity status](parity-status.md).

Use the selected device only, preserve a local before-image before writes, and retain failures honestly. Synthetic tests do not establish hardware recovery, power-cycle persistence, Linux GUI behavior or calibrated physical output.
